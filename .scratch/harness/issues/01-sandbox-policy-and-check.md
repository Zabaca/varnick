# Establish the sandbox under `srt`

**Status:** ready-for-agent

**Realizes:** `sandbox.checking`, `sandbox.available`, `sandbox.unavailable`

The `checkSandbox` actor is a stub that resolves after 250ms. This slice makes it generate a real `sandbox-runtime` policy from `SandboxPolicy` and establish it, so that `sandbox.available` means the kernel agrees rather than that a timer fired.

The policy is generated by the Harness package and stays editable in the clone — the thing a fork most wants to change is the boundary. Scoped to the clone: home directory, other repositories and the network denied except for the allowlist, `packages/core/**`, `vite.config.*` and `package.json` unwritable ([ADR-0002](../../../docs/adr/0002-core-userspace-boundary.md)), and `security`, `osascript`, `open`, `sudo` denied by denying *read* — `srt` has no execute allowlist.

The Agent SDK's own `sandbox` option is disabled and must stay disabled: the kernel refuses to apply a sandbox inside an existing one and every `Bash` command dies with exit 71. [ADR-0003](../../../docs/adr/0003-containment-wraps-the-process-tree.md).

**Done when** `sandbox.unavailable` is reachable by breaking the policy on purpose and carries the real reason as `sandboxError`, and the `#/states → sandbox-unavailable` card reads the same as it does today with a seeded failure.

**Refuses:** there is no state meaning "running without confinement" and none may be added. A policy that cannot be established is a failed run.

Covers stories 1, 3, 4, 5, 6, 10, 33.
