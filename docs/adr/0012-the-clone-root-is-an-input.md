# The clone root is an input, so a Workspace is per clone rather than per machine

The directory the agent works in used to be a path compiled into the Rust binary. `project_root()` in `src-tauri/src/bridge.rs` was `env!("CARGO_MANIFEST_DIR")`, and `env!` is a compile-time macro — the literal appeared twice in `src-tauri/target/debug/varnick`. **It was not where the process ran.** Launching that binary from anywhere named the machine it was built on; the two only ever agreed because `bun tauri dev` is `cargo run`, which recompiles in the checkout every time.

From there nothing passed it. The direction was the reverse of the intuition — the host did not *read* a working directory, it **set** one, and the value propagated by being that directory: the host spawned the runtime with `.current_dir(project_root())`, `runtime.ts` called `establishSandbox()` with no argument, and `sandbox.ts` fell back to `cloneRoot = input.cloneRoot ?? process.cwd()`. Four hops, and the careful comment at the end — "the clone the Sandbox was established for, not one chosen here" — was protecting a value that had arrived by accident, because nobody had ever chosen it.

**The root is now a named, validated input.** `VARNICK_CLONE_ROOT` chooses it; the compile-time constant is what it defaults to; the Tauri host resolves it once and passes it to the runtime as an argument rather than as a working directory. `bun tauri dev` in a checkout behaves exactly as before.

## What changes about what varnick *is*

`CONTEXT.md` defines a **Workspace** as "the environment a person builds around themselves inside their clone". That sentence is unchanged and it is now load-bearing in a way it was not: a Workspace is per **clone**, and a clone is chosen at launch, so one machine can hold more than one Workspace. It used to be one machine, one clone, one Workspace — true by construction and stated nowhere.

The one place that had quietly assumed otherwise was the Session mirror. It lived at `<app-data>/com.zabaca.varnick/sessions`, one directory per *machine*, and the live Session id is a constant (`LIVE_SESSION_ID`) — so two roots would have appended to one file and each would have shown the other's conversation. It is now keyed by root, at `<app-data>/com.zabaca.varnick/workspaces/<clone-name>-<digest>/sessions`. Still outside the clone, because ADR-0008's third consequence is that the agent cannot tamper with the record of what it did; keyed by the clone, not kept in it.

## Rejected

- **Leaving it fixed and only writing it down** (the ticket's reading one). Defensible, and cheaper: one clone, one Workspace, one root, and the only defect is that a load-bearing decision was expressed as a compile-time constant. It was rejected knowing this is the less reversible direction — once somebody runs a second root, taking it away breaks their setup and four subsystems have to give the parameter back.
- **A launch argument.** `bun tauri dev` is `cargo run` under the Tauri CLI, so a flag has to survive two argument forwardings to reach the binary; and Tauri's own argv is contested by single-instance and deep-link handling. An environment variable reaches both the host and, through it, the runtime, with nothing in between to lose it.
- **A setting the window asks for.** The largest of the options and the worst-shaped. `SandboxManager.initialize()` returns early once a Sandbox exists rather than replacing it, so a root chosen in the window would establish the first choice and silently ignore every later one — a control that does nothing after its first use. Re-establishing while the app runs means tearing down srt's proxies, the violation monitor, the agent process and the Session that rides it. Whatever eventually offers this, it is not this decision.
- **A setting stored in the clone.** Ruled out for the reason `agent.ts` already gives for `VARNICK_INHERIT_CLAUDE_CONFIG`: the agent can write its own clone, so a root stored there is a fence the agent can move. It also has to be readable before anything is rendered.
- **Reading `VARNICK_CLONE_ROOT` in the runtime as well as the host.** Two readers of one variable are two answers waiting to disagree, and the Sandbox and the mirror have to be about the same directory. The host resolves it; the runtime takes the argument and refuses without one.

## Consequences

- **Four subsystems now say which root, and each says it the same way.** The Sandbox policy takes `cloneRoot` and no longer defaults to `process.cwd()`; the Session mirror is keyed by it; the Core/Userspace write boundary joins every `denyWrite` entry onto it, so two roots are two boundaries; Surface discovery is the exception, below.
- **A root that is not there is a refusal that names it.** Checked twice, guarding different things: in the host before the spawn, because `Command::current_dir` on a missing directory fails as a bare io error the host can only report as `no-runtime`; and in `establishSandbox` before a policy is generated, because that is the gate that holds when it is called from a test or by hand. It used to surface as `ENOENT … open '<root>/sandbox-policy.json'` — a file nobody created inside a directory nobody has.
- **Surface discovery still names the build root, and cannot name another.** `import.meta.glob` is resolved by Vite at transform time and cannot take a variable, so the Surfaces in the window come from the tree the renderer bundle was built in. Point `VARNICK_CLONE_ROOT` elsewhere and the agent writes Surfaces into that tree while the window shows this one's. This is the same seam ADR-0008 records as unsolved for packaging — varnick's own code resolving relative to the repository it was built in — and closing it means a run-time Userspace loader, not a wider glob, because ADR-0004 requires each Surface import stay dynamic and individually catchable.
- **A second root's agent cannot yet reach varnick's own Agent SDK.** `agentSdkEntry()` resolves the SDK from the runtime's installation, which is the build root, and the policy reads back exactly the chosen clone out of the denied `$HOME`. So an agent started in a second root under a home directory cannot open the SDK it was handed the path to. Not fixed here, because the fix is either resolving the SDK from the chosen root or adding a path outside the clone to `allowRead`, and the second widens the boundary — which is a decision, not a detail.
- **Two roots on one machine are isolated for writes, and now very nearly for reads.** `allowWrite` is the chosen clone, the OS temp directory and Claude Code's scratch directory, so a second root's agent cannot write the first. Reads used to be allow-by-default outside `denyRead`, which left a clone outside a home directory (`/opt`, `/srv`, `/Volumes`) readable from any other root — ADR-0003's fourth correction, reached by a second route. Ticket 18 denied the filesystem root, and `allowRead` names one clone, so a second root is unreadable wherever it is kept. The remainder: a clone that happens to sit *inside* an allowed system tree is still readable, and the OS temp directory is allowed for both, so two roots under `$TMPDIR` can read each other.
- **The mirror written before this is adopted once, by the first root to launch.** There is nothing on disk recording which root the old flat directory belonged to — it held one mirror because there was one root — so the only honest reading is that it belongs to whoever arrives first. Moved rather than copied, so a second root finds nothing and starts empty instead of inheriting a conversation twice. Leaving it would have resumed an existing developer into an empty conversation over a file that is not empty, which is what ADR-0009 exists to prevent.
- **The runtime cannot be started without a root any more.** `serveHarness` lost its `hostCapabilities()` default and `serve.ts` refuses an absent argument instead of falling back to `process.cwd()`. Running the runtime by hand means passing the root — `bun packages/harness/src/serve.ts <clone-root>`.
- **The launch gate asks for one thing more than the library gate does.** `cloneRootFromLaunch` requires the directory be a varnick clone, because the agent host varnick starts is `<root>/packages/harness/src/agent.ts` and a root without one fails as an interpreter error naming a file the developer never chose. `requireCloneRoot` deliberately does not ask: every containment probe in the Harness establishes a Sandbox over a temporary directory, and those are roots without being clones.
