# A pane's turn comes from hooks that write to the pane folder, and peers send it in the relay's replies

Varnick learns whether Claude is working, waiting, or waiting on a permission dialog, a question, a plan or an MCP request from hooks it adds to the `--settings` every Claude pane starts with, beside ADR 0001's SessionStart hook. Each hook writes one word to a file in the pane's folder, only when the word changes (except `UserPromptSubmit`, which always writes working), so the file's date is when that turn began. That file on the session's host is the only source of the word (`Stop`'s input is also saved, for background shells, below): the app reads it for its own panes, and the relay reads it for `status` and `sessions` (protocol 12), on a Mac and on the headless host. A pane that starts claude writes the first word itself, so a session started again isn't read as its last run's turn. Problem and options: `docs/problems/session-turns-not-visible/`; this records option 01.

## Considered Options

- **The terminal-title glyph (option 02)**: rejected. It is undocumented, only known where a client is attached, and can't tell dialogs apart.
- **A notification-based marker**: rejected. Notifications carry no tool name, so a question's or a plan's `permission_prompt` would overwrite its own mark; `PermissionRequest` is the one marker for every dialog.

## Consequences

- The claude command line changes on every host, and with it what Skip permissions means: a session started with permission prompts on gets one more hook (`PostToolBatch`), one started with them skipped doesn't. (Wrong, see the amendment of 2026-10-09 below: a session that skips permissions can still show a dialog.)
- Protocol 12 means rebuilding both Macs and reinstalling the relay (ADR 0009).
- Sessions started earlier have no turn until restarted.
- Every host's Claude Code must ignore hook events it doesn't know: the settings are one value, so one it rejected would take the SessionStart hook with it. 2.1.291 ignores them; 2.1.285 is unchecked.
- Esc mid-turn and a plain Deny fire no hook (2.1.291), so the reader (`PaneFolder.corrected`) reads the transcript's last 64 KB when the file's word isn't waiting and the transcript is newer than the file, and returns waiting, dated by the user's interrupt entry. It never rewrites the file. The marker is a user entry with no `origin` whose text block starts "[Request interrupted by user", last among the conversation's entries, and no entry in the tail is stamped later (agent teams write a teammate's message just before an older-stamped automatic marker, and Claude goes on). Entries that are `isMeta` or a local command's (`<command-name>`, `<local-command-`, `<bash-input>`, `<bash-std`) are skipped, so `/effort` after an Esc doesn't undo it, while a task notification or a prompt is conversation and ends it. A tool result's `toolDenialKind` alone isn't a marker, since a command blocked by policy carries it too and Claude goes on. Only the session file's date and the transcript's are statted each second; the path and the tail are read when those change.
- A turn that ended with background agents, workflows or shells running is `background`, which the reader derives and no hook writes: when the corrected turn is waiting, the tail's last `turn_duration` entry (`pendingWorkflowCount`), less the workflow task notifications after it, is the workflows' count. Agents were counted there too (`pendingBackgroundAgentCount`) until the amendment below. It shows as Running, and peers get only the word. The design is in option 01's Background work.
- Shells count as agents do (amended 2026-10-07, at the user's request), from `Stop`'s input saved to `.varnick-stop`, not the transcript. That is one more change to the claude command line: a host not rebuilt, or a relay not reinstalled, shows a shell-only turn as Stopped. The design is in option 01's Background work.
- Agents come from `Stop`'s input too, and named agents (teammates) count while busy (amended 2026-10-08, at the user's request). Claude Code 2.1.295 stops writing `turn_duration` once a session spawns a named agent, so the transcript's agent count read 0 and a lead with agents running showed Stopped. A teammate stays `running` in the input after it goes idle, so the reader takes busy or idle from the lead's transcript (idle notifications, and the lead's messages and spawns), matched to the task by description. That reads the whole transcript, not its tail, when a teammate is listed: once and then only what is added in the app, and on every ask in a relay, which is a new process each time. The design is in option 01's Background work.
- Every pane gets `PostToolBatch`, and a dialog's answer gives back the word it replaced (amended 2026-10-09, at the user's request). The first Consequence assumed a session started with Skip permissions never shows a dialog, which is wrong, and the mark stayed after the user approved. Subagents and teammates also run the lead's hooks and write the lead's turn file, so a request from one of them marked the pane and the answer wrote working over an idle lead. The hooks' settings no longer depend on Skip permissions; panes already running keep their old hooks until they are started again. The mechanism is in `docs/agents/where-it-breaks.md`.
- A turn that stopped on an API error is `failed` (amended 2026-10-14, `sessions-finish-unnoticed` option 01). `StopFailure` writes waiting, as it must for the shells it keeps, so the reader makes the word, as it makes Esc's waiting and background: when a waiting turn has no background work and the last conversation entry in the transcript's tail is Claude Code's API-error entry (an assistant entry with `isApiErrorMessage`, its kind in `error`), dated no earlier than `PaneFolder.staleWindow` before the turn began, `PaneFolder.corrected` returns `failed` with the kind: "rate limit", "overloaded", "server error", "authentication failed", else "API error". Background wins, and an Esc's waiting is never read for it. Like background it is never written to the turn file and travels to peers as text, with no kind, and with no protocol bump: an older Mac reads the word as unknown and shows "Turn not known", and the headless relay reports waiting for it until reinstalled. The board puts it in Stopped with the mark "API error". The result also gains a local flag for a waiting made from the user's Esc, which the notices (`SessionNotifier`) use to stay silent. No hook changes. The entry is as undocumented as Esc's interrupt text, so a Claude Code that renames it reads the turn as ordinary waiting.
