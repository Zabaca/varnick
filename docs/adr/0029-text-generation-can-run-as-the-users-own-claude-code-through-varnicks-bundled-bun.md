# Text generation can run as the user's own Claude Code, through Varnick's bundled Bun

Hey Varnick's answers, and its decide step whenever TypeSafe's Jev doesn't decide, were written by Gemma 4 E2B on this Mac or by a model server the user runs. The Claude subscription that Varnick exists to run was never used for them. Text generation now has a third choice, **Claude Code**, which writes the text with the user's own `claude`, logged in as their panes are, on their subscription. It is the default for installs that never chose, and installs that already answer with Gemma keep **On this Mac**. The problem and its options are in `docs/problems/text-generation-ignores-the-claude-subscription/`; this records option 01.

Each text goes to **the text helper**: a copy of `bun` shipped in `Contents/Helpers`, running `agent.js`, which `bun build` makes from `TextHelper/agent.ts`. The entry calls `@zabaca/agent`'s `run` with `minimalOptions()` on Claude Haiku 5.5 (`claude-haiku-5-5`), with effort `low` (what stops Haiku 5.5 thinking; `thinking: disabled` is accepted and ignored), which sends no tools, none of the user's settings, hooks, plugins, CLAUDE.md or memory, no Claude Code reminders (the package's filter plugin, shipped beside `agent.js` as real files and passed by its path), no session-title call and no third-party logs: one request to Anthropic. Varnick adds the user's own `claude` as the executable, no saved transcript, an empty working folder of its own and partial messages. The prompts and the clean-up stay Varnick's, as for a server (ADR 0014); Claude Code only computes. Varnick runs `bun --no-env-file` on `agent.js` once per request, writes one JSON line to its input and reads JSON lines back.

The helper runs with **the environment the user's login shell builds**, read once per launch the way a pane's shell is started, with what ties a call to a pane or a session and any `ANTHROPIC_API_KEY` removed. Some users' Claude login is something their shell sets up (a credential proxy and a token in the startup files); a Varnick started by launchd has none of that, and a call made with its own environment gets a 401 or retries for minutes. Varnick stays agnostic about how the user logs in.

When Claude Code can't answer (`claude` missing, logged out, offline, at the plan's limit, an error, or no reply within the deadline, a few seconds, which is how a failing login shows) the text is written by this Mac's Gemma if it is installed, and Claude Code rests for a minute. Gemma becomes optional: a **Fallback on this Mac** row offers its download, and Hey Varnick no longer needs it to be turned on.

## Considered Options

- **Plain `claude -p` with the levers copied as flags (option 02):** passed over. The flags would drift from zbc's, the reminders filter is untested from the command line, and a one-shot `-p` has no path to a warm helper.
- **A helper compiled with `bun build --compile`:** passed over after the signing spike. It needs the same entitlement, but its reminders filter resolves inside Bun's virtual file system, where `claude` can't read it and skips it with only a log line; the compiled binary loads a `.env` and `bunfig.toml` from its working folder unless both are turned off at compile time; and it can't later run anything else.
- **The Anthropic API with a key in the Keychain (option 03)** and **one Claude conversation kept open (option 04):** passed over.
- **An allowlist of Varnick's own environment for the helper:** replaced by the login shell's environment, which an allowlist would miss.
- **The SDK's own bundled Claude Code:** 226 MB in the app, and a login of its own rather than the user's.

## Consequences

- **What leaves the Mac changes.** With Claude Code chosen and Hey Varnick on, Anthropic gets what the user asks out loud (cut to 500 characters), and for the answer step the kind, title, site or folder, date and description of the few results it reads (for a Claude session its prompts, paired Macs' too). That is the first time History and Bookmark rows go to Anthropic through Varnick. It rests on Hey Varnick being off by default and naming Anthropic where it is turned on, and on keeping existing Gemma users where they are. Amends ADR 0015's "on this Mac or … the user's own server … and nowhere else", ADR 0014's "over a cloud provider" and ADR 0012's expectation that a cloud choice would come with a key under Keys. `docs/privacy-and-security.md` says it.
- **The helper carries the user's shell environment,** whatever the shell exports, other services' tokens included, as a pane's `claude` does. It stays in memory, is never logged or written, and goes only to `bun` and `claude`. With no tools the model can't read it back. A change to the shell's startup files reaches Varnick at its next launch.
- **A second signed executable in the bundle.** `bun` is signed inside out (never `--deep`) with its own identifier, the hardened runtime and `com.apple.security.cs.allow-jit` alone. Without it JavaScriptCore loses its JIT and `SharedArrayBuffer`, and the Agent SDK fails at import. Bun's own four other entitlements are not needed. The signing spike (a throwaway app, notarized and stapled, a quarantined copy run) is the evidence.
- **Bun is a build dependency,** pinned by version and SHA-256 in the `Makefile` and fetched like zmx. The same binary builds `agent.js` and ships. `@zabaca/agent` and the Agent SDK are pinned exactly in `TextHelper/package.json`, and the packages install from the committed lockfile, without the SDK's optional native Claude Code packages.
- **The Agent SDK drives a `claude` it didn't ship with.** A mismatch with a newer `claude` makes every call fail into the fallback until the pins move. The row and the timing line say so.
- **The SDK's licence** is "all rights reserved, use subject to Anthropic's legal agreements". The user's decision: build now, and read those agreements before the first release that ships the SDK. Option 02 is the way back.
- **The plan's usage limits are shared with the panes,** and a spoken request that Jev doesn't decide makes two calls.
- **Existing installs are kept:** `local` is stored once at the first launch of this build for an install with Hey Varnick on or Gemma installed. An older build reads `claude` as unknown, which gives `local`.
