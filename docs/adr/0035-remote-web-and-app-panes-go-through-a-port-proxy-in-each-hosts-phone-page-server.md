# Remote web and app panes go through a port proxy in each host's Phone page server

Amends [ADR 0011](0011-each-host-serves-the-phone-page-behind-tailscale-serve.md) (one door, 8444, through `tailscale serve`) and [ADR 0007](0007-varnick-peers-reach-each-other-over-ssh.md) ("No listening port"), and ends the line of [ADR 0034](0034-a-tab-lives-on-one-host-which-keeps-its-layout-panes-and-mark-and-other-devices-view-or-take-over-the-tab-whole.md) that left an app and a web pane at a local address on a card "until option 04". A tab's web and app panes run on its host, at its localhost, where nothing else reaches them. The problem and the option are in `docs/problems/work-is-tracked-by-session-not-tab/` (option 04, with its spike).

The page server of each host also runs a reverse proxy. Another machine's pane loads `https://<the host's tailnet name>:<port>/` where the host's pane has `http://localhost:<port>/`:
- **One TLS listener per port, on the host's tailnet addresses only** (IPv4 and IPv6), for each port that a web or app pane of the host's open tabs uses: an app pane's port, and the port of a web pane on localhost, 127.0.0.1 or ::1. Each forwards to the same port on localhost, HTTP and websockets, bodies untouched. Only what a dev server checks is rewritten: Host (to localhost and the port), Origin when it is the proxied address itself, and a redirect to localhost, back to the proxied address.
- **Routing by port.** Each app keeps its own origin, so its storage is its own. Cookies are per name, so apps of one host share them, as on 127.0.0.1; the Phone page sets none.
- **The certificate is `tailscale cert` for the machine's name,** the one serve already keeps for 8444. It needs the user to be Tailscale's operator (`sudo tailscale set --operator=$USER`, once per host), or tailscaled run with `TS_PERMIT_CERT_UID`. It is asked for only while a port is wanted, with a minimum validity, and a new one is served by stopping each listener and serving it again: Bun's reload of TLS options keeps the old certificate.
- **A port opens only while its server answers on localhost and nothing else answers on the tailnet address at it,** and closes when that stops, at the next look (every 5 s, and when a page asks) or at once when a forward finds localhost refusing. A listener opened first keeps a server bound to every address from starting on Linux, and on a Mac it takes over the traffic of one already there. Never a port below 1024, never one `tailscale serve` publishes, never the page's own, never every address.
- **Who gets in:** `tailscale whois` on the connection's own address, shared with the page's cache. A device the host lists, or the node of a Mac it lists as a peer, found by its tailnet name from the relay's `hosts`; only a node of the user's own, never a tagged or shared one.
- **What a browser may ask:** `Sec-Fetch-Site` `same-origin`, a page loaded whole (`Sec-Fetch-Dest: document`), and a page loaded into a frame by a page of the same site (the phone's tab view). Another port of the same name is `same-site`, as is every host of the tailnet, so "not cross-site" would let any app reach every other with the viewer's identity. Without the header an Origin must be the proxied address.
- **The listing says where.** `tabs` gives each web and app pane at a local address a proxied address, or the reason it has none (`proxy`, `proxyNote` on `PeerPane`; protocol 25). The page server writes its tailnet name, the ports it holds and each pane's address or reason to `proxy-status.json` in Varnick's support folder (the state folder on a headless host) at every look, and the relay reads it. A file older than a minute means the page server isn't running, and the listing says so. The page server asks `tabs` and `hosts` as the host's own id, the one id the relay answers those two for besides a listed Mac's or device's; it is told what a device is.
- **On the viewer.** A Mac loads the proxied address in the pane's web view, in place of the card, which stays for a pane that can't be proxied and says why. A load refused for a pane the listing says is proxied is told as the Phone page server not running. The phone frames it in the tab's view with Open alone beside it, and its content rules allow frames from the host's own name.

## Considered Options

- **Routing by path prefix or by subdomain,** one `tailscale serve` per pane, and pixel streaming: rejected by the user in the problem (they leak cookies between apps, need a certificate per name, or move pixels, not pages).
- **The relay on a Mac as the proxy:** it runs for one request and exits, so nothing would listen between requests. The page server is the process that runs all the time on both kinds of host, and the headless host has no Varnick.
- **The proxy inside Varnick on a Mac:** the headless host has no Varnick, and the page server outlives a restart of Varnick.
- **SSH port forwarding from each Mac:** the phone has no SSH, so the phone would need the proxy anyway, and there would be two ways.
- **Letting pages reach another port of the same host, by rewriting Origin and `Access-Control-Allow-Origin` between the host's proxied ports:** not done. It fixes only pages that build the other port's address from their own host name, and it lets every open app call every other with the viewer's identity. A page that needs a second server reaches it through its own dev server's proxy (Vite's `server.proxy`), which keeps it same-origin. Recommended in the spike and not yet confirmed by the user, so it is the easiest decision here to reverse: `checkProxyFetch` and `rewrite*` in `PhonePage/proxy.ts`.
- **A `ports` request of the relay, with no identity,** for the page server to read: rejected for asking `tabs` and `hosts` as the host's own id, which keeps the relay's rule that every request but a hello names a listed Mac or device (the host's own id is added for those two).

## Consequences

- **A new door, on the tailnet,** on the ports the open tabs use. It is never public: Funnel reaches only serve mounts. The user's custom apps have no sandbox and no login, and today only this machine reaches them; with this, every listed device and paired Mac does too.
- **The machine's name was already in the public certificate logs** from serve's 8444, so the proxy adds nothing there.
- **A protocol bump to 25.** Every Mac and the headless host run one commit, as for any bump.
- **Requests between two ports of a host break,** where they work on localhost. They are documented as broken in the `custom-apps` skill.
- **An app that writes `http://127.0.0.1:<port>` into its pages still breaks from afar** (mixed content, and the wrong host), and so does Vite's fallback socket, which goes to the viewer's own 127.0.0.1.
- **A server bound to every address answers on the tailnet address itself,** over plain HTTP, as it already does. The proxy leaves its port alone and the pane says why.
- **On Linux, a server that binds every address and restarts within a few seconds can fail to start,** because the proxy holds the tailnet address at its port until its next look; the port is also closed at once when a forward finds the server gone.
- **First use needs Tailscale's operator** on the host (or `TS_PERMIT_CERT_UID`): one command with root, per host. Settings › Peers on a Mac says so, with the command, while a port is wanted and there is no certificate; the pane on the other machine says it too.
- **A headless host lists no web or app pane today** (its tabs hold Claude sessions and terminals), so its proxy is idle there and never asks for a certificate. The installer sets the unit's environment for it.
- **The tailnet address is looked at every 5 s** for each port a tab names, by a connect to localhost, which a dev server sees as a connection that sends nothing.
