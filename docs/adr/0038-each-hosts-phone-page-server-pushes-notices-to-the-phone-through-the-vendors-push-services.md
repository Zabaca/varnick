# Each host's Phone page server pushes notices to the phone through the vendors' push services

Amends [ADR 0011](0011-each-host-serves-the-phone-page-behind-tailscale-serve.md) (the page server answers the tailnet and asks nobody outside it), and reads the turns [ADR 0010](0010-a-panes-turn-comes-from-hooks-that-write-to-the-pane-folder.md) describes. The problem and the option are in `docs/problems/phone-page-is-only-a-browser-tab/` (option 02, accepted 2026-10-14, with the user's decisions of that day).

The page server of a host sends a standard Web Push (RFC 8030, VAPID RFC 8292, payload encryption RFC 8291 `aes128gcm`) to the phone's browser when a Claude session of that host needs the user and the user is away from it. It is the first request the server makes outside the tailnet.

- **When something is worth a push** is `NoticeRule`'s table (sessions-finish-unnoticed, option 01), kept in `PhonePage/pushrule.ts` for the host's own `tabs`: Done, Needs you (permission, question, plan, MCP input) and Stopped on an error with its kind. The first word read for a pane is a starting point; a waiting made from the user's Esc or Deny raises nothing. A change to the table, the failed word or a kind's wording is a change to both languages, and a test reads the Swift table to say so.
- **Where it goes** depends on the pane's controller, the Mac or device in its control label (the host when the label names nobody). A Mac whose user is present gets its own notice and the phone stays quiet, even when the notice stands for hours; when that Mac turns away with the notice still standing, the push goes then. A Mac that is away, or can't be told (no report for 20 s, or a peer Mac whose client is detached), and a device in control get the push after a 10-second settle. A device with the pane's terminal or live view open gets none. A Mac that isn't the controller is not asked: the phone is pushed even if the user is sitting at it (a Take over fixes that).
- **Present** means the screen unlocked, the display awake, the login session the active one and the last input under 2 minutes ago, computed in the page server alone from raw facts (idle seconds and an away flag), so the threshold lives in one place. Each Mac reads them (`PresenceReader`: the hardware's input counter, the display's sleep state, and the lock and session notifications, none needing a permission) and writes its own to its host's presence file, and adds them to the `status` request it already sends each host every 5 s; the host's relay writes a listed Mac's report to that Mac's file. A device's report is ignored.
- **A notice is read again before it is pushed.** The turn file is written just before the transcript says whether background work or an error goes with a waiting, so the page server asks `tabs` fresh at the end of the settle and pushes only what still holds. An error that follows its waiting in the same turn takes over the Done's settle.
- **What a push carries** is a version, the tab's and pane's ids, the kind and, for an error, its kind's word: never a title, prompt, folder, project or screen. Every payload is padded to one size (512 bytes before encryption) and every push is sent alike (one-hour TTL, high urgency, no Topic), so the push service sees that a push went, when, to which browser, and nothing that tells one kind from another. The service worker asks the host for the session's title over the tailnet with a 3-second deadline when the push arrives; off the tailnet the notification names only the host. The title never passes through a push service.
- **Where a push may go:** only to an https address on port 443 at Google's, Apple's, Mozilla's or Microsoft's push hosts, with no redirect followed, no IP address and no credentials in it. Without this a listed device could make the server send a request to any address, its own localhost and the tailnet included, and in loopback mode any local process could by posing as a device. A send has a 10-second deadline; 404 and 410 drop the subscription; 429 and a server error are retried once after Retry-After or 30 s and then dropped. At most one push per pane per settle and 60 per device an hour. The token's contact is Varnick's public site, never the user's email. The log holds the device's name, the kind, the status and the time.
- **One key per host,** a P-256 pair, with a subscription per browser bound to its public half. On a Mac Varnick makes it the first time it starts the server and keeps the private half as a Keychain item of its own, giving it to the server in its environment alone; the server's session carries a label with the key's fingerprint, so a different key restarts it. An item that exists and can't be read (an ad-hoc build refused after a rebuild) is never replaced, and the server runs without push until it can be read. On a headless host the server makes the key at its first start and keeps it as an owner-only file in its own owner-only folder, beside the proxy's certificate. A lost key is made again; subscriptions carry the fingerprint of the key they were made for, so old ones are dropped and each page subscribes again at its next load, without asking.
- **Subscriptions** are one owner-only file written only by the page server, at most four per device, each with the three switches (Needs me, Done, Errors, all on by default). A device that is no longer listed loses its subscriptions at once. Settings › Peers › Devices says which devices get notifications from this Mac, from a count in that file, never an endpoint.
- **Watching costs a stat, not a relay.** The server watches only while a subscription exists. It reads the date of each Claude pane's turn file every 2 s and asks `tabs` as the host's own id when one changed, when the saved tabs changed, when a pane folder appeared, every 15 s while a pane is in background or a notice stands, and every 60 s otherwise. One ask serves this and the port proxy. The page server is told the controllers' ids in `tabs`, which a device is not (`PeerTab.hiding(keepingControllers:)`).
- **Protocol 27** carries what the rule needs from other machines: an optional presence on a Mac's `status` request, the Esc mark and the failure kind on a pane's turn in `status` and `tabs`, and the controllers' ids for the host's own page server. A Mac that follows a peer's pane now takes the Esc mark and the kind, so a peer's Esc raises no Done there and its error names its kind. Every Mac and the headless host run one commit.

## Considered Options

- **Varnick's Mac app sends the pushes:** a headless host has no app, a card on the host is silent, and Web Push would be written twice.
- **The controlling Mac decides and asks the host to push:** two deciders, since the host must still decide for the phone and for a Mac that can't be told.
- **The host asks each Mac for its presence:** a headless host can't reach a Mac, and the Mac already reports every 5 s.
- **Escalating by time** (a push N seconds after a Mac notice even with the user present): rejected by the user, it buzzes the phone at the desk.
- **Asking `tabs` every 5 s:** about 17,000 Varnick processes a day on a Mac.
- **The title in the encrypted payload, or a push app such as ntfy:** the title would pass through the push service (encrypted, but sized and timed with the session), and ntfy adds a server and an app.

## Consequences

- **A third party carries every push.** It can't read the payload, but sees when and how often, from which address, to which phone.
- **A key per host that must never change by itself.** A Keychain item that is refused leaves the host without push until the user allows it; replacing it would void every subscription.
- **Presence is a guess at attention.** A user reading for two minutes without touching anything counts as away. Every case where a host can't tell (an asleep Mac, an older build, a dropped link) pushes rather than stays silent.
- **Presence reaches a host only from Macs that follow it,** that is, with a pane on it. The lock notifications are undocumented names (`com.apple.screenIsLocked`, `com.apple.screenIsUnlocked`); the idle counter and the display state are public.
- **A host that is asleep or offline sends nothing,** and a push is held at most an hour.
- **The page server reads Varnick's files:** the turn files, the presence files and the saved tabs' date.
- **Not verified on a phone at build time:** whether a service worker's fetch counts as `same-origin` for `Sec-Fetch-Site` (the title read; without it the notification names the host), how long iOS lets a push event run, and whether iOS honours a notification's `tag`.
